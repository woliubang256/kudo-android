# Agent Note: 网络管理中的并发与滑动窗口调度

Status: proposed

## Problem

已有RequestCooldown在429后阻止同源继续请求，图片另有4个响应体许可证，但API与图片没有共享的主动请求节奏。快速浏览可以在收到首次429前集中发出请求，用户也无法调整。用户要求参考FluxDo的并发与限流设置，已确认预设、自定义、即时生效和恢复默认的方案。

## Proposal

按scheme/host/port共享并发名额与滑动窗口，请求开始前等待本地额度；同源按进入顺序放行。并发覆盖响应体读取，EOF、关闭或异常只释放一次。网络拦截器接入API、Connect和图片，每次真正的HTTP交换都计数，缓存命中不占额度；DoH开关不改变调度。长轮询、原图/大文件下载、GitHub更新和WebView继续走各自通道，不占短请求名额。

默认均衡为并发3、每3秒6次；省心为2/6/5，极速为6/15/3。自定义范围为并发1～10、阈值2～30、窗口1～10秒。配置独立存储，不触发DoH重连；更新立即唤醒等待者，缩小并发不取消在途请求，扩大窗口仍参考最近10秒的请求历史。排队沿用现有调用总超时，每100ms以内检查取消与服务端冷却。冷却使等待者立即失败，写请求不自动重放。

设置入口与页面标题改为网络管理，保留DoH/ECH、VPN和服务器管理。底部新增高级区，预设按钮用LogoYellow选中态，高级参数可折叠，自定义时展开。恢复默认使用现有液态玻璃弹窗，只重置请求节奏。

## Existing note audit

检索限流、并发、RequestScheduler与请求调度。[主站冷却与图片退避](../../implemented/bug-fix/2026-10-14-request-rate-cooldown.md)部分重叠，保留429、图片4路上限和单次安全恢复，在其上增加可配置的同源共享门限；[DoH网络](../../implemented/feature/2026-10-12-doh-network.md)部分重叠，保留路由、凭据边界及写请求不重放。通知流与网络传输修复不改变。无完全吸收或过时提案。

## Reference

参考FluxDo快照e1bd839的request_scheduler_config.dart、rate_limit_card.dart和请求调度行为，仅借鉴交互、参数与调度意图，独立编写Kotlin实现，不移植GPL源码。

## Implementation status

核心RequestScheduler与网络拦截器已实现，8项离线测试通过（artifacts/request-scheduler-core.txt）：共享并发覆盖正文、窗口精确到期、扩大窗口保留历史、动态调整、等待取消、异源隔离、429打断等待、逐跳计数与读取失败释放。配置持久化、客户端接入及设置页面仍按本提案继续实现。

## Alternatives considered

- 只增加设置界面接入OkHttp Dispatcher最省改动，但无法在多个客户端间共享窗口，响应回调结束也不代表正文下载完成。
- 在页面仓库方法外包一层协程锁可避免占用网络线程，但容易遗漏图片和重定向；在实际交换处统一约束，保留调用现有超时和取消。
- 将长轮询和下载一起限制最统一，但长连接会长期占满看帖名额；保留它们各自的生命周期和并发控制。
- 429后排队恢复可免手动重试，但会积压过时请求并有重复提交风险；本地平滑排队与服务端强制冷却分别处理。

## Acceptance criteria

- 用离线测试验证同源共享、异源隔离、滑动窗口边界、动态参数、排队取消、响应体释放及429打断等待。
- 验证API/图片接入、Cookie与重定向边界、写请求只发送一次以及DoH下的行为。
- 真机验证预设、自定义滑块、折叠、重置确认/取消、持久化和DoH设置回归，覆盖安装保留数据。
- 分核心调度、持久化与接入、页面三个单元提交，提交前校验笔记。

## Risks

本地设置只能降低请求突发，不能消除账号/IP等服务端限流。极速模式仍受429冷却约束。网络线程等待额度有现有总超时兜底；正文必须按OkHttp契约关闭或读完才能归还名额。图片原有4路保护保留，调高共享并发不能突破该局部上限。
