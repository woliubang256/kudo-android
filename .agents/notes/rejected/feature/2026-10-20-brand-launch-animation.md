# Agent Note: 启动时三色拆解重组品牌

Status: rejected — 600ms 飞散版真机观感一般，用户改选 750ms 连续变形；由[连续重组](../../implemented/feature/2026-10-20-brand-launch-morph.md)替代。

## Problem

启动目前使用系统默认的酷 DO 静态图标。用户要求先显示 LinuxDO，再让黑、白、黄三色飞出来重组为酷 DO；明确拒绝两张图切换和仅原地变形，并确认约 600ms、只用真机验证。桌面应用图标不更换。

## Proposal

使用 core-splashscreen 1.2.0 接入系统启动层，第一帧为带安全留白的 LinuxDO 矢量。系统退出回调中，在同一启动层、同一图标坐标用 Canvas 矢量绘制替换静态图标，不加第二个 Activity 或独立 Compose 启动页。首页和原有请求正常启动，不以网络就绪作为动画完成条件。

600ms 分为 80ms 原标志、160ms 飞散、300ms 回旋重组及 60ms 收稳衔接。黄色下弧向左下飞后展开为圆角底板；黑色上弧拆为三片，分别沿上方弧线飞出并重组为 K 笔画；白色向右飞后收拢为右下圆点。碎片位移、旋转、缩放与轮廓连续，途中不叠放两张整图或用透明度切换伪装重组。首尾使用现有品牌的精确路径，中间轮廓采样只在初始化计算，逐帧复用 Path。

动画只在新建 Activity 的首次启动播放；回到后台任务不重播，状态恢复直接移除启动层。动画受系统时长缩放控制，关闭动画时不等待。Activity 停止或销毁时取消并移除启动层，结束只执行一次，避免覆盖已恢复页面、泄漏窗口或吞掉新 Intent。普通链接、通知和下载入口仍由 MainActivity 原逻辑处理。

## Existing note audit

- 按启动页、启动动画、SplashScreen 精确检索，无同主题现存提案或已实现决定。
- [原生社区客户端](../../implemented/architecture/2026-10-07-native-community-client.md)部分重叠：保留 API 26 起的兼容范围、Application 容器初始化及 singleTop Intent 处理；只接入启动层，不改账号与网络配置。
- [双品牌关于页](../../implemented/feature/2026-10-10-about-settings.md)部分重叠：复用两套既有品牌，不替换图标或改关于页。
- 其余 Logo 关键词命中为列表、导航、通知、表单和主题选中颜色，无本次决定取代；不归档这些独立笔记。

## Alternatives considered

- 系统 AnimatedVectorDrawable：可在应用首帧之前由系统播放，原生集成最少；但多片轨迹和轮廓重组在旧系统支持、图标圆形裁切与精确进度验收上更复杂。本次用官方退出回调内的矢量 Drawable，沿用同一系统启动层，600ms 从该回调可绘制时开始，不声称覆盖进程初始化耗时。
- 额外 Splash Activity 或整屏 Compose 页：可以自由安排几何与时长，预览也方便；会产生系统启动页后又一页的衔接、额外导航或重复播放风险，因此只扩展现有启动层。
- 两整图交叉淡变：资源和实现成本最低，但用户明确否定，不能作为拆解重组的替代。

## Acceptance criteria

真机确定性绘制验证初始帧与 LinuxDO、结束帧与现有酷 DO 矢量一致，飞散阶段三色位于不同轨迹、超出原图范围，连续中间帧不是两整图淡变，全部片段留在可绘制区域。检查主题启动图标与应用图标不同且保留原桌面图标。实机冷启动录屏核对首帧、飞散、重组和首页衔接，另检查后台恢复、重建与动画取消，不用模拟器。

## Risks

600ms 是品牌动画，不是整个冷启动耗时；进程和容器初始化可能更久。系统/OEM 启动层位置与回调时机需要实机检查，旧版兼容不能由 Android 13 真机代替。三片轮廓的中间形状有设计取舍，最终观感由逐帧和正常速度录屏判断，不能用像素测试宣称稳定帧率。
