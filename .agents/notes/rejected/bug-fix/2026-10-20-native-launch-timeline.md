# Agent Note: 系统启动阶段播放品牌动画并平衡首尾停留

Status: rejected — 用户真机否定提前播放的效果，恢复原 Canvas 节奏，仅延长酷 DO 显示并在 750–900ms 整层淡出；采用[连续变形](../../implemented/feature/2026-10-20-brand-launch-morph.md)。

## Problem

750ms Canvas 动画从首页首帧后的系统退出回调才开始。LinuxDO 先占据整个系统启动等待，又占据动画开头，酷 DO 仅在末尾定格，用户实机看到两端明显不均衡。只改退出动画内的停留常量不能扣除系统等待。

## Proposal

Android 12 / API 31 起将同一组连续变形轮廓内置为系统 AnimatedVectorDrawable，在系统启动阶段播放，不等待首页首帧。时间线为 LinuxDO 150ms、连续重组 360ms、酷 DO 150ms，末尾启动层淡出 90ms，共约 750ms。退出回调只延续系统图标的剩余时间，不替换图标、不重播变形。系统已播放时间从 iconAnimationStartMillis 读取；首页准备较晚时保留一次短淡出，不能承诺进程初始化也在 750ms 内。

API 26–30 仍使用现有透明像素边界交接及 Canvas 兼容方案，时序与原生资源一致，不改初始化、Intent、桌面图标、后台返回及取消契约。

## Existing note audit

- [连续变形](../../implemented/feature/2026-10-20-brand-launch-morph.md)部分重叠：本提案曾尝试取代 API 31+ 等待退出回调才起播的选择，但用户真机否定后不再落地。原篇保留 Canvas、品牌几何、无二次启动页及生命周期约束，改为 900ms 总时长与末尾 150ms 整层淡出。
- [飞散原型](../../rejected/feature/2026-10-20-brand-launch-animation.md)无新增决定，仍不恢复飞散。

## Alternatives considered

- 仅提前结束变形、延长酷 DO 定格：改动最小，但 LinuxDO 仍独占首页准备期，实际曝光不对称且总显示期继续叠加。
- 先画空首页再接 Compose：可提早进入可控动画，但改变 Activity 首帧和内容装配，主线程首次组合仍可能阻塞动画；系统 AVD 可以在启动层独立播放，不需要增加导航或空页面。
- 系统 AVD：先前因轮廓和裁切复杂被放弃，但它能在首页准备前起播，是本次消除额外 LinuxDO 停留的直接方案；成本是同时维护兼容画法和平台资源，测试必须验证时间线与几何一致。

## Acceptance criteria

先以真机资源类型断言复现静态启动图标，再验证平台 AVD、两端各 150ms、750ms 总预算、退出不重播和晚准备时不追加完整动画。保留首尾像素、连续变形及取消测试。使用同版本同开发签名覆盖安装，检查优化包真实冷启动的首尾曝光、无尺寸跳变和后台恢复。

## Risks

系统启动窗口进入、进程初始化、OEM 以及系统动画缩放影响实际曝光；保证设计时序均衡而非宣称所有冷启动严格等长。旧系统没有原生 AVD 启动支持，不能由 Android 13 验收代替其覆盖。
