# Agent Note: 已发布主帖与回复编辑

Status: implemented

## Problem

原生编辑器只发布新内容，自己的已发布主帖和回复缺少编辑入口。将编辑复用为发布会新增楼层，正文 HTML 也不能作为编辑原文。

## Decision

读取 /posts/{id}.json 的 raw，以作者 ID 和 can_edit 同时校验自己的编辑权限。PUT 同一 post ID，保留 Markdown 原文及图片地址，用 post[original_text] 检测冲突，主帖标题使用顶层 title。编辑草稿按账号和 post ID 独立保存，保存成功原位更新楼层与标题。失败保留输入，不自动重放写入。

## Existing note audit

[主题操作](../../implemented/feature/2026-10-09-topic-actions.md)部分重叠，保留举报与历史权限决策并互链。[账号与编辑器](../../implemented/feature/2026-10-07-account-and-composer.md)部分重叠，新发帖和云草稿契约继续有效。[酷安表单](../../implemented/feature/2026-10-10-coolapk-forms.md)部分重叠，沿用扁平输入和工具栏，编辑发布内容采用独立页面。[回复目标提示](../../implemented/feature/2026-10-10-editor-target-hints.md)与此次保存契约无关，不修改。

## Alternatives considered

扩展发布接口最能复用现有表单和草稿流程，但 POST 会新建帖子，编辑应单独建模，只共享表单呈现。由 cooked 反推 Markdown 无额外读取成本，却会丢失图片短链、引用和格式，所以必须读取 raw。
