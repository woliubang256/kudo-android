# Agent Note: 小程序音乐接入系统媒体控制

Status: implemented

## Problem

用户对比 QQ 音乐小程序与本应用，发现本应用播放时没有出现在系统媒体卡片，期望也能被支持媒体控制的灵动岛识别。

改动前 MiniAppMusicService 只有 CATEGORY_TRANSPORT 的普通前台通知和暂停操作，没有 Android MediaSession、PlaybackState、MediaMetadata 或 MediaStyle。网页桥只报告歌名、歌手、播放状态与部分控制能力，不包含封面、播放进度和时长。暂停停止整个服务，因而不能直接保留供系统继续播放的媒体会话。

## Decision

沿用已确认的 Music Player 白名单和原网页播放器，现有宿主服务提供平台 Android MediaSession 与 MediaStyle 媒体通知。系统播放、暂停、上一首、下一首回调通过现有控制桥执行原网页按钮；只暴露网页实际支持的操作，不另建播放器或重复请求音源。

媒体状态随真实播放变化更新。首次播放之前不激活媒体会话；暂停后在原小程序仍存在且可控制时保留可继续的会话，并退出前台播放状态；关闭对应小程序、账号切换或页面失效时注销会话及通知。异步更新必须绑定同一账号与应用键，旧状态与旧按钮不能控制后续会话。

系统媒体卡片以真实播放为入口，不要求用户先收起小程序。应用内音乐入口继续遵循[既有音乐浮层规则](../../implemented/feature/2026-11-07-mini-app-music-floating-control.md)：只有对应收起条目存在时显示；恢复只隐藏入口，音乐条关闭只暂停并隐藏，关闭小程序停止音乐。

会话与通知共用同一 token，通知操作使用每次会话独有的随机标识，系统回调绑定控制器实例；旧控制器、旧通知按钮与旧会话不能操作后续播放器。通知点击恢复原小程序任务。暂停时保留已启动的会话和通知，并退出前台播放状态；首次加载但未播放不创建卡片。

白名单网页适配器读取实际 track-title、track-artist、track-album、elapsed、duration、seek 与前后切歌按钮的状态，不访问播放器私有对象。拖动进度按原进度条的范围换算数值并触发原 change 事件。时间缺失或不可解析时不提供进度，时长上限为 24 小时；网页显示按秒取整，因此系统进度可能存在约一秒误差。前后切歌能力分别上报与校验。

原应用的封面是 opaque sandbox 内创建的 blob，网页桥只对现有图片绘制最长边 320px 的 JPEG 缩略图，编码上限 100000 字符；不加载新音源、不暴露原生接口给子框架。封面按歌曲与当前图片地址的标识绑定，只在图片变化时传输；普通进度更新不重传。换歌或图片消失先清理旧封面，读取失败保留无封面状态。官方主框架继续校验当前地址、账号、应用 ID、消息来源与字段类型，总消息限制为 110000 字符。

原生后台解码前校验编码格式、长度和图片尺寸，拒绝边长超过 512px 的图片；换歌、关闭与会话切换取消旧解码任务。系统 metadata 和通知大图使用同一缩略图，元数据只随歌曲内容或封面变化更新；时间更新只刷新 PlaybackState，不反复发布通知。可用时发布时长、当前位置及 ACTION_SEEK_TO，缺失时不伪造能力。

实现按系统会话与控制、网页元数据与封面、真机回归分开提交，每个实现小单元最多修改三个源码或测试文件。

## Related decisions

检索非归档笔记中的 MediaSession、音乐和系统媒体控制：现有[音乐白名单与网页控制](../../implemented/feature/2026-11-07-mini-app-music-floating-control.md)与[小程序浮窗任务](../../implemented/feature/2026-11-07-mini-app-floating-windows.md)部分关联，保持既有职责，不取代它们。Sentry 提案无关。本决定补充系统可识别的会话边界，不把通知权限、系统媒体展示策略与音乐白名单混为同一个能力。

## Alternatives considered

- 每个音乐小程序分别实现系统通知最容易贴合其页面，但重复会话生命周期并增加后续维护成本；标准系统媒体服务共用，差异只留在白名单网页适配器。
- 使用原生播放器和完整媒体播放框架能统一音频焦点、媒体源及播放进度，但会替换网页播放器的执行逻辑，可能破坏鉴权、歌单与播放策略；本次仅桥接既有播放器，使用平台 MediaSession，不引入独立音源。
- 只改善现有普通通知改动最少，但不能补齐系统识别和系统媒体控制契约，不能满足用户提出的播放卡片需求。
- 原生按封面地址请求图片可以复用常规图片加载库，但线上应用实际使用 opaque runtime 内的 blob 地址，无法在原生侧解析；由现有图片导出限尺寸缩略图，不增加外部图片请求或原生对网页网络能力的旁路。

## Testing

RMX2202 / Android 13 的新增系统媒体集成测试先失败：播放状态已从不透明 iframe 上报，但 MediaSessionManager 查不到本应用的会话（artifacts/mini-app-system-media-repro-device.txt）。接入后同一测试通过，覆盖歌名、歌手、播放状态、通知 token、系统暂停与继续、前后切歌、关闭后注销及旧会话不能恢复播放（artifacts/mini-app-system-media-session-device.txt）。测试通过原网页按钮及真实暂停回调核对操作，网页使用离线 fixture，不等同于线上音乐或厂商灵动岛实测。

封面与进度的新增集成测试先因缺少 metadata 封面失败（artifacts/mini-app-system-metadata-repro-device.txt）。最终 MiniAppMusicFloatingUiTest 十项真机测试通过（artifacts/mini-app-system-media-verified-device.txt），新增覆盖 sandbox 内 blob 封面、专辑、真实时间字段、系统拖动进度触发原 change 事件、切歌更新封面、无封面时清理旧图、只加载未播放不创建系统卡片，以及无效编码和超尺寸图片回退。保留并通过既有浮窗恢复、关闭、材质、账号切换和横向预览用例。

系统控制测试等待关闭操作的原网页暂停回调完成后才检查旧会话，避免把异步暂停误判为旧控制操作。Debug / AndroidTest 构建、MiniAppMusicStateTest 和 lintDebug 通过；开发版保持 3006 / 0.3.5-dev，覆盖前核对签名一致，全程没有卸载或清除数据。自动审批拒绝 ADB 打开线上音乐小程序（blocked by policy），因此本轮不声称线上播放或厂商灵动岛实测通过。

## Consequences

系统现在能通过标准媒体契约识别宿主并控制原播放器，无需增加播放框架或独立音源。暂停会话与后台服务仍可能被系统回收，不提供进程死亡后的播放恢复。没有真实数据的进度使用未知位置，不伪造封面或时长；跨域图片无法安全导出时只显示文字信息。

厂商灵动岛或第三方实现可能使用标准媒体会话，也可能要求额外权限、用户配置或厂商合作接口，不能承诺接入后所有机型自动显示。封面与进度能否提供取决于实际网页能力，不能单凭系统接口存在就承诺完整展示。网页失活、进程回收与播放状态迟到需要明确释放策略，不能遗留假播放或不可操作的系统卡片。
