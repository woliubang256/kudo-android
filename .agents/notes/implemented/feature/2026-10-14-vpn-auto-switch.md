# Agent Note: 可关闭的 VPN 自动切换

Status: implemented

## Problem

DoH 目前在检测到 VPN 或系统代理时无条件暂停。用户已为 L 站配置直连分流，希望 VPN 开着时仍能使用 DoH/ECH；默认仍保留现在的规避代理行为，并参考 FluxDO 截图的“VPN 自动切换”文案。

## Decision

按配置/网络与设置界面两个小单元实施。DohConfiguration 新增默认 true 的 vpnAutoSwitch，沿用 version=1 JSON 的可选字段扩展；旧配置缺字段、非法类型及损坏配置都保持自动切换开启。总 DoH 开关与此选项独立保存。

自动切换开启时，VPN 或系统代理令原生 DoH 暂停；断开后按总开关恢复。关闭自动切换时，即使检测到 VPN/系统代理也可创建原生 DoH/ECH 通道，连接检测遵守同一条件。切换设置或网络使旧通道失效，沿用现有写请求不重放、Cookie 与 ECH 校验边界。

设置位于 DoH 页面，名称“VPN 自动切换”，说明“检测到 VPN 或系统代理时自动暂停 DoH，断开后恢复”。界面只描述 App 实际管理的 DoH；原生通道继续不使用系统 HTTP 代理，VPN 的直连/代理出口由用户的分流规则决定，App 不绑定底层网络以绕开 VPN，也不修改 VPN 配置。

## Existing note audit

检索 VPN、自动切换、规避代理和 DohConfiguration。[DoH 接入](../../implemented/feature/2026-10-12-doh-network.md)部分重叠：本篇为原来的无条件暂停加入用户可选的例外，旧策略仍是默认，保留其原生 TLS、会话、监测与 WebView 边界。与[原生探针](../../implemented/testing/2026-10-12-doh-ech-device-probe.md)相关但不改其历史验证；[原生下载](../../implemented/feature/2026-10-14-native-download-manager.md)复用相同路由，无独立策略改变。客户端验证仅为测试背景。无完全吸收或过时提案，不归档旧篇。

## Alternatives considered

- 只忽略 VPN、继续无条件规避系统代理：范围最小，但与原有同一规避策略和截图的自动判定语义不一致，用户无法在系统代理环境自行选择；一个开关统一控制这两个已支持的检测来源。
- 增加上游代理与 VPN 判定方式选择：更接近 FluxDO 完整网络页面，但本次只需要自动切换开关，现有自动检测可覆盖所需场景，不引入新的代理或判定模式。
- 关闭自动切换时将 Socket 绑定到非 VPN 网络：能强制直连，但会绕开用户分流规则且受系统网络与 UID 能力限制；保留默认网络，让 VPN 按用户规则分流。

## Testing

JVM 覆盖旧配置默认、false 往返、非法类型安全默认，以及总开关/自动切换/VPN/系统代理的完整状态矩阵和状态文案；定向 18 项通过。DohSettingsUiTest 覆盖默认开启、关闭、隐藏后重新显示仍保留选择和说明文案；已有节点管理与默认 VPN 暂停用例继续覆盖。

真机本机回环服务器用例覆盖 VPN 与系统代理模拟状态下关闭选项后真实使用 Rust Socket，重新开启后恢复基础客户端，总开关关闭始终停用 DoH；两个路由场景均通过。回环夹具显式使用 `Proxy.NO_PROXY`，避免真机当前系统代理把本地请求送到代理并返回 503（此前表现为 MockWebServer 请求数为 0）。设置界面测试使用测试 APK 私有配置，不修改用户订阅、VPN 或生产节点。

## Consequences

关闭自动切换不保证流量直连；VPN 分流规则或网络能力仍可能使原生通道走代理。这里增加选择权，不改变 ECH 必须真实协商成功的约束。旧版本 App 若重新保存配置会忽略新字段，下次升级回到默认开启；不更改既有 JSON 主版本以避免清空节点配置。检测状态仍展示实际 VPN/代理，但只有自动切换开启时才显示暂停。
