# Agent Note: 本地优选的慢网络保留、静态资源共用节点与 IPv6 偏好

Status: implemented

## Problem

本地优选冷启动先校验缓存赢家，TCP、ECH 握手与 trace 请求共用 3 秒预算。移动网络刚唤醒或出口约 1 秒 RTT 时，一次校验约需 3.3 秒，超时即被当作失效，随即整轮竞速；竞速同样只有 3 秒单次预算，全部超时后进入 `fallback`，Kotlin 侧收到 `fallback` 就删除持久化赢家。结果是一次慢启动让下次正常网络也要从头优选。

静态资源域 `ldstatic.com`（cdn、cdn3、ping、上传桶）强制 ECH，却仍按所选 DoH 的答案连接；CFluxDo 1.3.0 记录福建等地头像、表情大面积失败和上传 502，原因是静态域落在被干扰的地址上而主站经优选可用。

竞速只按延迟取最快者，IPv4 几乎总是胜出；随机 IPv6 样本又取自 Cloudflare 公布的整个 /32，CFluxDo 实测这类地址多半没有路由。双栈家宽的 IPv4 出口常是运营商共享地址，Cloudflare 风险分更高、更常弹验证（CFluxDo 用户日志 4.5 天 39 次）。我们的 WebView 走系统网络，Chromium 在双栈网络通常经 IPv6 访问论坛，原生通道固定在 IPv4 时两者出口不同，网页取得的验证凭据可能对不上；这一点是推断，尚无对照数据。

2026-11-09 对照 CFluxDo 1.3.0（加速核心 `c18d48d..b6acc0c`，其中 `c8f034c`）确认同一问题，对方在 1.1 秒延迟出口实测冷启动 8.3 秒降到 3.9 秒。

## Decision

只把“超时”当作可能的慢路径，给一次放宽预算（8 秒）的复核；连接被拒、ECH 被拒、站点不符等确定失败不复核。

- 缓存赢家：3 秒预算超时后，用放宽预算对同一地址再探一次，通过即钉住，不收集候选也不竞速。
- 竞速：单个候选超时即停止换钥匙重试（超时属于路径而非密钥）；整轮无人通过时，取最多 4 个超时候选，按放宽预算并发复核一次，不额外消耗竞速配额。
- 竞速失败：只是超时的缓存赢家留在原生内存的 `retained` 中，下一次获准的选择先校验它；状态 JSON 新增 `forget`，仅在缓存赢家确定失败、密钥失效或实际流量连续建连失败时为 `true`。
- Kotlin `persistedEdgeWinner` 只在 `fallback` 且 `forget` 不为 `false` 时删除持久化赢家；旧原生库不带该字段，保持原有删除语义。

`edge_pool::covered` 同时覆盖 `linux.do`、`ldstatic.com` 及其子域：这些主机共用同一赢家地址与赢家携带的 Cloudflare 公共 ECH 密钥，静态域的建连失败同样计入赢家连续失败。2026-11-09 公共解析确认 cdn / cdn3 / ping / linuxdo-uploads.s3 均为 Cloudflare 并发布 ECH。赢家仍只用主站 trace 验证；静态域若在赢家上不可用，会经连续失败解除钉住并回到所选 DoH。

IPv6 偏好：每次选择以 UDP connect 检查本机有无到公网 IPv6 的路由（不发包，只有链路本地或缺默认路由时视为无）。有 IPv6 时，候选按 IPv6、IPv4 交替排进首批探测，并抽 8 个而非 4 个 IPv6 样本；IPv4 先通过时最多再等 1.5 秒 IPv6，最终除非 IPv6 既慢一倍以上又慢 300 毫秒以上，否则选 IPv6。无 IPv6 时排序与选择规则不变。IPv6 样本只取 Cloudflare 代理站点使用的 /48（`2606:4700::`、`:10::`、`:20::`、`:3030::`–`:3037::`），接口标识嵌入共享池 IPv4（104.18–104.27、172.64–172.71），与 linux.do、ldstatic 的实际 AAAA 形态一致。

赢家新增 `v6_considered`（反序列化缺省为 false）：由偏好 IPv6 的竞速选出或本身是 IPv6 时为 true。有 IPv6 的网络上，未与 IPv6 比较过的 IPv4 缓存赢家不做校验，直接竞速一次；该竞速失败时它按“只是超时”保留，不标记 `forget`。之后存下的赢家都带标记，同一赢家不会反复触发迁移竞速。状态 JSON 附 `prefer_v6` 供诊断。

被保留的赢家从不直接作为路由，仍须重新验证；网络切换跳过缓存赢家的既有策略不变。探测与候选收集经 `Network` 注入，离线用例以“按预算返回”的假探测模拟慢网络，不真实等待。

## Alternatives considered

- 把单次预算整体提高到 8 秒：实现最简单，慢网络一次即过；但每个不可达候选都会拖满 8 秒，正常网络的冷启动和竞速窗口一起变长，因此只对已超时的地址放宽。
- 竞速失败也立即删除赢家（原行为）：保证存储里只有最近验证过的节点；但慢网络下的删除没有证据，代价是下次正常启动重新优选，且缓存赢家本来就要重新验证，所以改为保留。
- 静态域单独优选或单独钉住：可分别适配不同区域的节点；但两个域名属于同一 Cloudflare 共享池与同一 ECH 密钥，单独竞速要多一轮探测和冷启动等待，CFluxDo 也按共用处理，因此共用主站赢家。
- 照搬 CFluxDo 的“IP 协议”设置与后台换族竞速：用户可手动固定 IPv4，旧赢家先照常钉住、后台再赛 IPv6；但要新增设置项和后台竞速状态，与“无定时后台测速、少用说明文字”的现有约束冲突，因此只做自动偏好，只迁移一次未比较过的旧赢家，代价是该次冷启动多等一轮竞速。
- 继续纯按延迟选择：最简单，也最快；但 IPv4 在延迟上通常略占优，偏好永远不会生效，而出口质量（共享地址的验证频率）在延迟上看不出来，因此给 IPv6 一个“慢一倍且多 300 毫秒”的容忍度。

## Testing

Rust 离线 36 项通过（新增 5 项）：慢赢家放宽一次即钉住且不竞速、确定失败不复核并标记 `forget`、全超时竞速放宽复核至多 4 个、竞速失败保留慢赢家并在下一轮先校验、流量连续失败标记 `forget`。临时把逻辑改回旧行为时，其中 3 项失败。JVM 新增 `onlyAKnownBadWinnerLeavesStorageWhileASlowRaceKeepsIt`，DoH 相关 28 项通过。

静态资源与 IPv6 合计后 Rust 离线 44 项通过：域名覆盖边界（含 `ldstatic.com.evil.test`、`evilldstatic.com`）、IPv6 样本形态、选择容忍度、交替排序、双栈竞速选略慢的 IPv6、旧 IPv4 赢家迁移一次且失败仍保留、已比较赢家照常校验、旧存储缺省字段。

2026-11-10 RMX2202 / Android 13，`0.3.8-dev` / `3009` 以原开发证书（SHA-256 `95f95aff…3e4f`）覆盖安装，未卸载或清数据。`EdgeSelectionDeviceTest` 在线 2 项通过（13.778 秒）：`linux.do`、`connect.linux.do`、`cdn.ldstatic.com`、`ping.ldstatic.com` 解析到同一赢家且 ECH 均 Accepted，trace 各自返回本主机；缓存赢家重新验证通过，过期密钥经 retry_configs 恢复。该 Wi-Fi 分配了全局 IPv6 地址，但只有 `/60` 网段路由、没有 IPv6 默认路由（`ping6` 报 Network is unreachable），用例记录 `preferV6=false`、赢家为 IPv4，确认缺默认路由时不误判。有 IPv6 默认路由的网络上选中 IPv6 赢家尚未在真机验证。同次 `latest.json` 返回 HTTP 403，与此前在线记录一致，属站点策略，不能说明 IPv6 偏好的效果。


## Consequences

最坏情况下（缓存赢家与全部候选都只超时）一次选择多花约 8 秒放宽校验加 9 秒复核窗口，期间该主机的解析继续等待。真实但很慢的线路会被钉住，体验仍慢，只是不再反复优选。图片流量也会触发赢家失败计数，图片大量失败时主站会一起离开赢家。IPv6 生效后出口地址改变，已登录用户首次可能需要重新过一次验证；IPv6 线路若时通时断，只能靠连续失败解除钉住，没有手动固定 IPv4 的入口。
