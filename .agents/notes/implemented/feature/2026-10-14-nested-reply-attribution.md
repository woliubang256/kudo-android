# Agent Note: 楼中楼显示实际被回复作者

Status: implemented

## Problem

同一讨论里的直接回复与更深后代都显示“昵称：内容”，用户无法知道后代在回复谁。弹窗也只有当前作者。用户批准对齐酷安：直接回复原评论只显示作者，回复楼中楼显示“甲 回复 乙”。

## Decision

摘要和弹窗共用实际 replyTo 归属显示。父楼层是讨论原评论或主帖时只显示作者；其他合法的较早父楼层显示当前作者和该父帖作者。只在已加载的讨论内查找父帖，不为文案增加网络请求；父帖不可访问时显示实际 #楼层，不误用讨论根作者。忽略内容仍隐藏，但保留公开的回复对象；长名字沿用摘要两行和弹窗标题省略，不改变图片入口及跳转目标。

用户补充要求弹窗右上角保留“#楼层”，旁边以跳转图标替换文字入口；图标的无障碍说明包含实际楼层，仍沿用原楼层跳转和关闭面板。

弹窗的头像、时间和点赞/回复操作由[弹窗互动](2026-10-14-nested-reply-actions.md)补充，实际被回复作者和 `#楼层 [跳转图标]` 的展示决定保留。

## Existing note audit

检索活跃笔记的楼中楼、reply_to、回复对象及预览。[楼中楼分组](../../implemented/feature/2026-10-10-nested-replies.md)部分重叠，本篇取代隐藏“甲 回复 乙”的展示决定，保留父链分组、游标、祖先补齐和两行内联图片契约。[原楼层与预览](../../implemented/feature/2026-10-10-reply-timeline-and-preview.md)部分重叠，保留主时间线与辅助缓存、摘要跳转、预览不计读。图片角标、用户装饰、忽略用户与楼层跳转的决定不翻转。没有完全吸收或过时提案。

## Alternatives considered

- 所有回复都显示被回复作者：关系最完整，但直接回复原评论的目标已由外层评论说明，重复名字不符合用户指定的展示方式。
- 深层回复都显示讨论根作者：不需要查找直接父帖，但会把真实的回复对象改错；使用 replyTo 指向的实际父帖。
- 补请求被回复作者：缺失父帖也能得到昵称，但会为辅助文案增加请求并可能再次失败；只复用已加载数据，缺失时展示实际楼层。

## Testing

NestedReplyAttributionUiTest 的两项先在 RMX2202 / Android13 复现摘要和弹窗缺少回复对象（artifacts/nested-replies-2026-10-14/attribution-repro-device.txt）。新增五项覆盖直接回复、二级及更深回复、缺失/非法父楼层、忽略内容和窄屏 130% 字号内联图片，点击仍跳到当前回复原楼层；弹窗验证 #楼层和跳转图标。

与 ReplyPreviewImagesUiTest、NestedReplyUiTest、ReplyTimelineUiTest 共 18 项定向真机用例首轮有 16 项通过（attribution-fixed-device.txt）；缺失父帖夹具意外又放入同楼层作者，修正为真正缺失；旧忽略测试从不含 Text 的容器改为点击实际文字节点，保留精确隐藏文案与显式揭示断言。两项修正和追加楼层图标检查后，3 项复跑通过（attribution-final-device.txt），18 个不同用例均已验证。构建显式保留 2005 / 0.2.3，同一开发签名覆盖安装，不清理登录数据。已检查 nested-reply-attribution-preview.png、nested-reply-attribution-large-font.png，普通关系文字正确，长名字省略时仍保留可用图片入口。

## Consequences

缺失父帖只能显示楼层；过长作者名字在摘要中可能被省略。不能因无法展示昵称而猜测作者或阻止正文展示。
