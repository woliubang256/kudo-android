# Agent Note: 完整版本编辑历史页面

Status: implemented

## Problem

已有历史底部面板展示文字差异，不能按微博参考纵向阅读完整版本，差异扁平化也丢失图片。

## Decision

编辑历史在独立原生页面按新到旧排列，卡片显示编辑者、时间、说明、版本标题和完整正文。读取 revision 的 body_changes.side_by_side，从 revision-content --current / --previous 提取完整 HTML，去掉差异装饰后复用 RichContent 及图片预览。沿服务器 previous_revision 指针逐条加载，不按整数枚举版本。只有最早记录为 revision 2 且两侧可访问时追加原始版本，不将截断或隐藏历史伪称原始版本。

隐藏两侧或 diff_error 不展示正文，明确提示不可用，不用最新正文代替旧版本。更早版本加载失败保留已读版本并允许重试。主帖、回复、楼中楼的“已编辑”和操作菜单均进入同一页，返回不刷新话题。

## Existing note audit

[主题操作](../../implemented/feature/2026-10-09-topic-actions.md)部分重叠，本篇替代历史展示决策，原有权限和服务器指针、举报写入理由仍保留。[已发布内容编辑](../../implemented/feature/2026-10-15-post-editing.md)部分重叠，编辑保存和历史浏览分开建模，两个页面共享真实 post ID。[Discourse 数据契约](../../implemented/architecture/2026-10-07-discourse-data-contract.md)部分重叠，沿用原生正文及同源会话边界。

## Alternatives considered

原差异面板最适合逐字对照修改，但用户希望纵向看每次完整内容，所以改为版本列表。读取 /posts/{id}.json?version=N 能取得直接快照，但隐藏版本权限和可用版本不能靠数字枚举猜测，且额外请求增加开销；使用服务端已过滤的双栏完整 HTML 和指针。由 inline 差异反推版本能兼容部分数据，却无法可靠恢复图片属性变化，所以缺少双栏时提示不可用。
